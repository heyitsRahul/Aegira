AEGIRA SYSTEM
Working Prototype

Help, on any phone, without becoming a surveillance system.

Aegira turns a trigger into a consented, time-boxed, cryptographically mortal session. The power to see someone's location or summon aid exists only inside that session, and is permanently destroyed when it ends.

Problem

Privacy Trade-offs in Coordination

Emergency coordination systems often trade user privacy for utility, retaining sensitive location histories in persistent databases, cache files, logs, or analytics feeds. This introduces ongoing risk from data breaches, platform surveillance, or external subpoenas. Furthermore, many solutions require modern smartphones and stable internet connectivity, leaving feature phones and lower-end hardware unsupported.

Aegira solves this by ensuring location capability is strictly session-bound, using ephemeral cryptography for true data deletion, and providing accessibility channels for every tier of hardware.

Design Invariants

Four Differentiators

Session-shaped capability

No location ever exists outside a session — not in a table, cache, log, or analytics event.

Crypto-mortal data

Deletion means destroying the per-session key (crypto-shredding). What the platform cannot decrypt, it cannot leak or be subpoenaed for.

Duress by design

A duress PIN returns a response indistinguishable from success while silently escalating — for cancel and for journey check-in.

Runs on every phone

Smartphone app (PWA), a zero-JavaScript web version for old browsers, and a full SMS gateway for phones with no browser at all.

Interface

Three Access Channels

Aegira operates across three dedicated channels, ensuring complete device coverage from high-end smartphones to basic feature phones without internet access.

Channel For Route / Entrypoint
App (PWA) Smartphones /app

State of Development

What's Real vs. Stub

Aegira is a working prototype. Core logic, state machines, encryption mechanisms, and protocols are real and validated through 282 tests. Infrastructure integrations use pluggable stubs ready for production implementations.

Real & Tested

  • Session lifecycle + exhaustive state machine
  • Per-session crypto-shredding
  • Capability-token auth (3 roles)
  • Duress (cancel + journey check-in)
  • Journey watch / timed check-in
  • E.164 phone, country/helpline data
  • Restart-safe persistence, chain-verified

Stubbed & Pluggable

  • SMS delivery (StubSmsTransport / Twilio adapter ready)
  • KMS (InMemoryKeyVault; same KeyVault interface)
  • Responder network (seeded roster)
  • Push notifications
  • Production Postgres (SQLite adapter today)
  • Official-services (112) integration
